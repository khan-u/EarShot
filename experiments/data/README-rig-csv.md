# Pilot rig data and derived CSVs

The five `rig-rec-*.wav` files are preserved recorded evidence. Their CSVs are derived analyzer outputs; neither file type alone establishes physical timing accuracy. The pilot return channel is the phone adapter's electrical output, not a microphone at the listener's speaker.

## Two historical CSV variants

- `rig-latency-<stamp>-uncalibrated.csv` is the source of the reported unshifted latency estimates. It uses `analyze <wav> --min-corr 0.9 --min-lag-ms 30` with the other defaults and without median alignment. For example, the first accepted-event median is 151.680 ms.
- `rig-latency-<stamp>.csv` is the shifted intermediate from the historical live driver, which used `--est-median <software_median>`. That option shifts every latency by the same amount so the accepted-event median matches the supplied software KPI. This forced agreement is not independent calibration or validation. These files remain for provenance and should not be pooled with the unshifted CSVs.

`rig-software-medians.csv` holds the five historical laptop diagnostics (80, 81, 82, 73, 73 ms). Subtracting them from the corresponding unshifted capture medians gives a mean difference of 65.8 ms and sample SD 10.6 ms. Their direction and sampling window are unmatched to the recorded laptop-to-phone path, so these differences do not establish a physical device constant. The software model already includes a 40 ms additive term.

## Columns and acceptance

| Column | Meaning |
|---|---|
| `burst` | Reference-event index assigned by the analyzer |
| `t_ref_s` | Detected reference-envelope peak time on the WAV sample time base |
| `latency_ms` | Selected NCC lag with parabolic refinement; shifted only in the legacy intermediate |
| `corr_peak` | Highest NCC found in the specified lag window |
| `quality_db` | Selected return-envelope level relative to initial envelope RMS |
| `kept` | 1 when both correlation and quality thresholds pass, otherwise 0 |

There are 235 analyzed reference events and 201 accepted events. All 34 rejected rows fail the default quality threshold; none fail NCC >=0.9 at the baseline settings. Counts by capture are 53/56, 47/52, 32/40, 39/45 and 30/42 accepted/analyzed. The displayed CSV precision is 0.001 ms for latency; it is not a statement of measurement accuracy.

The mean ± sample SD of the five medians is 143.6 ± 9.2 ms; the pooled accepted-event mean is 155.3 ms. Capture 5 has an even accepted count, giving median 136.7125 ms from the displayed CSV values. Nine accepted estimates exceed 190 ms, including three above 400 ms. Acceptance by these gates does not independently verify the selected physical arrival.

## Reproduction and provenance

From the repository root:

```bash
make -C rig
bash experiments/compare-rig-runs.sh
# After installing the figure requirements in an environment:
python3 experiments/plot-rig.py
```

The shell command prints fresh summaries. The plot script re-analyzes every WAV and compares all CSV rows with the archived unshifted files before writing figures. Neither command changes the pilot data.

The EarShot artifact is `ea7d2c6a6d880a1c41d97e4ca533b17441202c93`. The revised drivers write new data to `experiments/runs/` by default. The archived JSON/JSONL telemetry also remains unchanged; its older field names and schemas should not be treated as evidence that it was generated by the revised drivers.

Physical checks remain necessary: the reference spacing and WAV durations differ from the nominal stimulus schedule; the measurement excludes the final listener transducer; and ambiguous peaks and crosstalk require controlled testing. See the [runsheet](../RUNSHEET-rig.md) and [root README](../../README.md).
